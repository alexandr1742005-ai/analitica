# Acceptance Criteria (Gherkin: Given / When / Then)

Версия: 1.0 | Трассировка: User Stories → Acceptance Criteria → Functional Requirements

---

### AC-01 — Регистрация клиента (US-01)

```gherkin
Feature: Регистрация клиента

Scenario: Успешная регистрация
  Given клиент находится на странице регистрации
  When клиент вводит корректные email, телефон, ФИО, дату рождения и пароль (мин. 8 символов, буквы+цифры)
  Then система создаёт новую учётную запись со статусом "active"
  And клиент получает подтверждение об успешной регистрации

Scenario: Email уже используется
  Given в системе уже зарегистрирован пользователь с email "ivan@example.com"
  When новый клиент пытается зарегистрироваться с тем же email
  Then система возвращает ошибку "Email уже используется"
  And новая учётная запись не создаётся

Scenario: Слабый пароль
  Given клиент вводит пароль короче 8 символов
  When клиент отправляет форму регистрации
  Then система отклоняет запрос с сообщением "Пароль должен содержать минимум 8 символов, буквы и цифры"
```

### AC-02 — Аутентификация (US-02)

```gherkin
Feature: Вход в систему

Scenario: Успешный вход
  Given клиент зарегистрирован в системе
  When клиент вводит корректные email и пароль
  Then система выдаёт access-токен
  And клиент перенаправляется в личный кабинет

Scenario: Блокировка после 5 неудачных попыток
  Given клиент 5 раз подряд ввёл неверный пароль
  When клиент пытается войти в шестой раз
  Then система блокирует учётную запись на 15 минут
  And возвращает сообщение "Учётная запись временно заблокирована"
```

### AC-03 — Идентификация клиента (US-03)

```gherkin
Feature: Идентификация по паспортным данным

Scenario: Успешная идентификация
  Given клиент аутентифицирован и не прошёл идентификацию
  When клиент вводит корректные паспортные данные (серия, номер, дата выдачи, кем выдан)
  And возраст клиента находится в диапазоне 21-65 лет
  Then система сохраняет паспортные данные со статусом verified = true
  And клиент получает доступ к подаче заявки

Scenario: Возраст вне допустимого диапазона
  Given клиент указывает дату рождения, из которой следует возраст 19 лет
  When клиент отправляет форму идентификации
  Then система отклоняет запрос с сообщением "Оформление кредита доступно с 21 года"
```

### AC-04 — Создание заявки (US-04)

```gherkin
Feature: Подача заявки на кредит

Scenario: Корректная заявка
  Given клиент прошёл идентификацию
  When клиент указывает сумму 500000, срок 24 месяца, цель "На ремонт"
  Then система создаёт заявку в статусе DRAFT
  And сохраняет параметры заявки без ошибок

Scenario: Сумма вне диапазона
  Given клиент указывает сумму 5000000
  When клиент отправляет форму заявки
  Then система отклоняет запрос с сообщением "Максимальная сумма кредита — 3 000 000 ₽"
```

### AC-05 — Загрузка документов (US-05)

```gherkin
Feature: Прикрепление документов к заявке

Scenario: Успешная загрузка документа
  Given у клиента есть заявка в статусе DRAFT
  When клиент загружает файл справки о доходах в формате PDF/JPG до 10 МБ
  Then система сохраняет документ и связывает его с заявкой
  And документ отображается в списке документов заявки
```

### AC-06 — Ограничение подачи при просрочке (US-06)

```gherkin
Feature: Блокировка подачи заявки при активной просрочке

Scenario: Клиент с просрочкой более 30 дней
  Given у клиента есть кредит со статусом OVERDUE более 30 дней
  When клиент пытается создать новую заявку
  Then система отклоняет создание заявки
  And возвращает сообщение "Невозможно подать заявку при наличии просроченной задолженности"
```

### AC-07 — Отправка заявки на рассмотрение (US-07)

```gherkin
Feature: Отправка заявки

Scenario: Успешная отправка
  Given заявка находится в статусе DRAFT и заполнена корректно
  When клиент нажимает "Отправить на рассмотрение"
  Then статус заявки меняется на SUBMITTED
  And запускается процесс идентификации/скоринга
```

### AC-08 — Автоматический скоринг (US-08)

```gherkin
Feature: Скоринговое решение

Scenario: Автоматическое одобрение
  Given заявка в статусе SCORING_IN_PROGRESS
  When скоринговый балл рассчитан как 750
  Then заявка автоматически переходит в статус APPROVED
  And результат сохраняется в ScoringResults с decision = "APPROVE"

Scenario: Автоматический отказ
  Given заявка в статусе SCORING_IN_PROGRESS
  When скоринговый балл рассчитан как 350
  Then заявка автоматически переходит в статус DECLINED
  And результат сохраняется в ScoringResults с decision = "DECLINE"

Scenario: Направление на ручную проверку
  Given заявка в статусе SCORING_IN_PROGRESS
  When скоринговый балл рассчитан как 550
  Then заявка переходит в статус MANUAL_REVIEW
  And результат сохраняется в ScoringResults с decision = "MANUAL_REVIEW"

Scenario: Внешнее БКИ недоступно
  Given условный сервис БКИ возвращает ошибку/таймаут
  When система пытается рассчитать скоринговый балл
  Then заявка переводится в статус MANUAL_REVIEW
  And в логе фиксируется причина "BKI_UNAVAILABLE"
```

### AC-09 — Очередь на ручную проверку (US-09)

```gherkin
Feature: Список заявок для оператора

Scenario: Оператор просматривает очередь
  Given существуют заявки в статусе MANUAL_REVIEW
  When оператор открывает раздел "Заявки на проверку"
  Then система отображает список заявок, отсортированный по дате подачи (FIFO)
```

### AC-10 — Решение оператора (US-10)

```gherkin
Feature: Ручное решение по заявке

Scenario: Оператор одобряет заявку
  Given заявка в статусе MANUAL_REVIEW назначена оператору
  When оператор выбирает "Одобрить" и указывает комментарий
  Then статус заявки меняется на APPROVED
  And в заявке фиксируется operator_id и время решения

Scenario: Оператор отклоняет заявку
  Given заявка в статусе MANUAL_REVIEW
  When оператор выбирает "Отклонить" без комментария
  Then система требует обязательный комментарий с причиной отказа
```

### AC-11 — Подписание договора (US-11)

```gherkin
Feature: Подписание договора через SMS-код

Scenario: Успешное подписание
  Given заявка в статусе APPROVED
  When клиент вводит корректный SMS-код подтверждения
  Then статус заявки меняется на CONTRACT_SIGNED

Scenario: Неверный SMS-код
  Given клиент вводит неверный SMS-код 3 раза подряд
  When клиент пытается ввести код в четвёртый раз
  Then система блокирует подписание на 30 минут
```

### AC-12 — Выдача кредита (US-12)

```gherkin
Feature: Выдача кредита

Scenario: Успешная выдача
  Given заявка в статусе CONTRACT_SIGNED
  When система эмулирует зачисление средств
  Then создаётся запись в Loans со статусом ACTIVE
  And рассчитывается график платежей в Payments (аннуитет)
  And заявка переходит в статус DISBURSED
```

### AC-13 — Статус заявки в кабинете (US-13)

```gherkin
Feature: Просмотр статуса заявки

Scenario: Клиент просматривает статус
  Given у клиента есть заявка в любом статусе
  When клиент открывает раздел "Мои заявки"
  Then система отображает текущий статус и дату последнего изменения
```

### AC-14 — График платежей (US-14)

```gherkin
Feature: Просмотр графика платежей

Scenario: Клиент просматривает график
  Given у клиента есть активный кредит
  When клиент открывает раздел "Мои кредиты" → детали кредита
  Then система отображает полный график платежей с датами, суммами и статусами (PLANNED/PAID/OVERDUE)
```

### AC-15 — Уведомления (US-15)

```gherkin
Feature: Уведомление об изменении статуса

Scenario: Изменение статуса заявки
  Given статус заявки клиента изменился с SUBMITTED на APPROVED
  When изменение зафиксировано в системе
  Then клиенту отправляется уведомление (email — эмуляция) о новом статусе
```

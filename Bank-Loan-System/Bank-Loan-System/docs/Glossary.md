# Глоссарий терминов

Документ фиксирует единую терминологию проекта. Все остальные документы (BRD, FR, NFR, User Stories, Use Cases, диаграммы, схема БД, API) используют термины строго в значении, определённом здесь.

| Термин | Определение |
|---|---|
| **Клиент (Client)** | Физическое лицо, использующее платформу для оформления потребительского кредита. Может быть неаутентифицированным (гость) или аутентифицированным (зарегистрированный пользователь). |
| **Заявка на кредит (Loan Application)** | Запрос клиента на получение кредита с указанием суммы, срока и цели. Проходит жизненный цикл от `DRAFT` до `CLOSED`/`DECLINED`. |
| **Кредит (Loan)** | Финансовое обязательство, возникающее после одобрения заявки и подписания договора. Создаётся из одобренной `LoanApplication`. |
| **Скоринг (Scoring)** | Автоматизированная процедура расчёта скорингового балла на основе анкетных данных, кредитной истории и внешних источников (условное БКИ). |
| **Скоринговый балл (Score)** | Числовое значение (0–999), отражающее оценку кредитоспособности клиента, рассчитанное скоринговым модулем. |
| **Скоринговое решение (Scoring Decision)** | Результат скоринга: `APPROVE` (одобрить автоматически), `DECLINE` (отказать автоматически), `MANUAL_REVIEW` (передать оператору). |
| **Оператор банка (Bank Operator)** | Сотрудник банка, принимающий решение по заявкам, попавшим в статус ручной проверки (`MANUAL_REVIEW`). |
| **БКИ (условное)** | Условный внешний источник кредитной истории (Бюро кредитных историй), эмулируемый в проекте таблицей `CreditHistory`. |
| **Идентификация (Identity Verification)** | Процедура подтверждения личности клиента по паспортным данным перед подачей заявки. |
| **Документы (Documents)** | Файлы, загружаемые клиентом (паспорт, справка о доходах и т.д.), привязанные к пользователю и/или заявке. |
| **Договор (Loan Contract)** | Юридически значимый документ, подписываемый клиентом при одобрении заявки. В рамках MVP подписание эмулируется (SMS-код / чекбокс согласия), сам PDF-документ не генерируется. |
| **Транш / выдача (Disbursement)** | Перечисление одобренной суммы кредита на счёт/карту клиента после подписания договора. |
| **График платежей (Payment Schedule)** | Список плановых платежей по кредиту (аннуитетная схема), хранится в таблице `Payments`. |
| **Просрочка (Overdue)** | Ситуация, когда плановый платёж не поступил в срок. Фиксируется статусом `OVERDUE` в `Payments` и `Loans`. |
| **Кредитная история (Credit History)** | Агрегированные данные о прошлых и текущих кредитных обязательствах клиента, используемые скорингом. |
| **Личный кабинет (Client Dashboard)** | Раздел платформы, где клиент видит статус своих заявок и кредитов. |
| **REQ-ID** | Уникальный идентификатор функционального требования (например, `FR-01`), используемый для трассировки между FR, User Stories и Acceptance Criteria. |
| **MVP (Minimum Viable Product)** | Минимально жизнеспособный продукт — объём функциональности, реализуемый в рамках данного проекта. |

## Статусные модели (единый источник истины)

### Статусы заявки (`LoanApplications.status`)
```
DRAFT → SUBMITTED → IDENTITY_VERIFIED → SCORING_IN_PROGRESS →
   ├─→ APPROVED → CONTRACT_SIGNED → DISBURSED → CLOSED
   ├─→ DECLINED
   └─→ MANUAL_REVIEW → (APPROVED | DECLINED)
```

### Статусы кредита (`Loans.status`)
```
ACTIVE → CLOSED
ACTIVE → OVERDUE → ACTIVE (после погашения просрочки)
ACTIVE → OVERDUE → DEFAULTED (после N дней просрочки, N=90)
```

### Статусы платежа (`Payments.status`)
```
PLANNED → PAID
PLANNED → OVERDUE → PAID
PLANNED → OVERDUE → DEFAULTED
```
